# M2 checkpoint — Android + KMP complete

M2 delivered the full Android app on the KMP core: the whole product with derived fields, list
cells, detail, search, filters and sort, pull to refresh with soft delete, the delegated-storage
port (batched and chatty) on the bundled SQLite with a settings picker, fixture mode, instrumented
UI tests, and benchmarks for every suite (boundary, core, delegated storage, app). Failure crosses
the storage port as a result, not an exception. The coverage gates held at 100% lines with no new
exclusion. The Ralph loop built every product issue; improver sessions built the doc and loop fixes
between them.

Sources: the `## Retro notes` comments on the 40 PRs that have one, review threads and failed check
runs on all 72 PRs merged after #130, CI runs on `main`, and the loop's session logs (40 issue
sessions, 8 improver sessions).

## What was hard

Patterns, each seen at least twice:

- **No working emulator.** The host ran several emulators and Android Studio's JVM in 32 GB, with
  a load average of 55–110 at times. A leased emulator either never booted or answered `adb shell`
  after 17–165 s, and Gradle then failed with `TimeoutException getting properties for device`.
  It cost most of five sessions (#168, #200, #201, #245, #248) and this checkpoint's bench run.
  #202 split the device run out of #122; `android/README.md` (#219) says to check adb by hand
  first. #265 is to fix it: the make targets check adb before they build.
- **Protected build files found mid-session.** A new module, dependency or build type means editing
  `android/app/build.gradle.kts`, which needs `gate-approved`. Sessions found this partway through,
  split out a gate PR and stopped with NEEDS_HUMAN: #167 (#119), #193 (#117), #205 and #207 (#124),
  #229 (#123). #266 is to fix it with a drafting check; the M3 drafts already apply it.
- **Compose and the coverage gates.** Generated skip and remember branches pulled the app under the
  95% branch gate whenever new code was pulled out into a composable or a lambda was written in one
  (#151, #165, #187, #215), and an exhaustive `when` in a composable left an uncovered line (#250).
  Each fix is in `android/README.md` (#159, #228, #255, #256), and #215 hit the lambda trap again
  after #187 recorded it, so the next repeat should get a check rather than another note.
- **Structural changes in a behavioural PR.** The review caught Extract Function on code already on
  `main` in #165, #169, #205 and #249, each costing a round or a split. #174 put the rule into
  `CLAUDE.md`'s refactor step; #205 and #249 came after it. #249's came from detekt's `ReturnCount`
  limit, which now appears in `android/README.md`'s list of size limits (#255). The review is
  catching every case, so no new fix.
- **Tests green on their first run.** #152, #164, #169, #172, #195, #201 and #249. The double loop
  (#179), the `TODO()` rule for compiler-forced branches (#209) and ordering screen tests before
  the fix under them (#254) each closed one cause.
- **SQLDelight's dialect.** `ON CONFLICT … DO UPDATE` (M1's #60, then #164), row values (#154) and
  `NOT deleted` (#164) each cost a build. #267 is to fix it with a note in a new `core-kmp/README.md`.
- **Adding a field rewrites every contract case that returns it** (#140, #141): the runner compares
  whole JSON values. Filed as the proposal #268.
- **Shapes and callers the issue left open**, M1's main pattern, recurred in a narrower form: a
  read's return type change reached callers no one listed (#220 split into #230–#232), and a module
  couldn't depend on the one the issue put its code in (#218, #248). The drafting checklist in
  `ISSUES.md` (#227, #240, #254) now asks for callers, module dependencies and failure paths.
- **CI red after a structural merge.** `test_blame_ignore_revs` failed on #154, #168, #176, #177 and
  #179 when a `Structural:` PR merged while they were open. Fixed by #211: the loop updates such PRs
  locally and lists the new commit.

## What the gates caught

- **Review, hard findings:** merge-conflict markers committed in `contract/README.md` (#154); a
  cursor that isn't a stored id returning an empty page (#154); structural extractions in
  behavioural PRs (#165, #169, #205, #249); device tests with no red run (#200) and screen tests
  green on first run (#249); a test kept after passing first time (#201); `SPEC.md` claiming the
  reads had no failure code (#214); a failed `COMMIT` on the Android port leaving the transaction
  open (#221); split-off PRs with no issue to close (#142, #192).
- **Review, judgement notes:** the contract adapters' duplicated maps (#141, #152, #153, #154; ruled
  acceptable in #180); a tautological expected title (#200); a non-scrolling detail screen (#151);
  an embedded median of 0 dividing by zero in the overhead column (#218, still open).
- **pr-size:** never failed. The largest PR was #140 at 383 lines; sessions split before writing
  code instead (below).
- **protected-paths:** fired as designed on 11 PRs, all merged with `gate-approved`.
- **CI:** five red runs from the blame-ignore check above; #187's was the last before #211.

**Got past the gates:**

- **Flaky tests on `main`.** `ProductListTest.choosingPriceLowToHighReordersTheList` failed CI on
  `main` after #211 and #219, and in #215's session; `StartupReportTest` failed on `main` after
  #245. Both wait with `waitUntil`'s 1 s default while paging loads. #257 is filed for it.
- **A failed page read crashed the list.** #233 left `ProductPagingSource` casting the result, so a
  storage failure became a `ClassCastException`. The session flagged it, and #242/#249 fixed it.
  The drafting check "Who calls it" (#240) now asks what each screen shows on failure.

## Coverage blind spots

- **Exclusions:** none added. core-kmp still excludes only SQLDelight output, the app only
  `MainActivity`.
- **Suppressions:** `@Suppress("ReturnCount")` on `ProductPagingSource.load` (#249) and
  `TooGenericExceptionCaught` in `EmbeddedStorage` (#212), each scoped to one function.
- **Covered but not really tested:** tests the 100% gate forces for compiler-required branches
  (`decodeReportsABodyThatIsNotJson`, #201) until #209's `TODO()` rule; the Compose
  remember-branch workarounds (#187, #215) cover generated code rather than behaviour.
- **Outside the gates by design:** `:uitest` and `:macrobenchmark` run only on a device, so `make
  coverage` never sees them; the bundled SQLite's natives can't load under Robolectric, so
  `SqliteStoragePort` is tested on the plain JVM (#215).

On Android, KMP is plain JVM bytecode, so the boundary rows measure a Kotlin call: sub-millisecond,
as `SPEC.md` expects.

The storage overheads in this run say more about the host than about delegation. Each variant is
its own instrumentation run, minutes apart, and the embedded run was the noisy one: its p95 was 2–10
times its median for every storage workload (ingest 100: 37.56 against 163.48), where the chatty
run's stayed within 1.3 times. An earlier run on a quieter host, at `1cc234e`, had embedded ingest
at 6.58 / 25.18 / 206.73 ms, batched within 13 % of it, and chatty five to six times slower.
Comparing the variants needs them interleaved in one run, or several runs per variant, rather than
one run each.

## One-off friction

Kept for the next retro to spot a repeat:

- `make test-core` prints only `FAILED`; the reason is in the JUnit XML (#152).
- Robolectric dropped a Compose main-looper post at teardown, so later tests hung on Loading; an
  outer `DrainMainLooper` rule fixes it (#155).
- `swipeDown` on a content-sized `LazyColumn` is too short to pull to refresh (#165).
- ktlint and detekt fought over one long line (#190); `make fmt` (#239) came later.
- Requery's `sqlite-android` has no JVM natives, so the port uses `androidx.sqlite:sqlite-bundled`
  (#193), which can't load under Robolectric next to other classes (#215).
- A `private companion object` val left one Kover instruction uncovered (#195, #248).
- `ReportDrawnWhen` never reports under Robolectric; the test supplies its own reporter (#245).
- Macrobenchmark's JSON shape was guessed from the docs until #204's first real run (#205).
- GitHub's closing-PR references include merged PRs even with `includeClosedPrs: false` (#206).
- A PR waited 27 minutes on another whose doc line its test read; the blocker wasn't listed (#222).
- A new trailing parameter bound existing trailing lambdas to it (#235).
- Cross-module `inline` fails between the core (JVM 21) and the app (JVM 11) (#221).
