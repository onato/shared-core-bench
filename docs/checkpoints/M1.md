# M1 checkpoint — Walking skeleton: Android + KMP

M1 delivered what `ISSUES.md` promised: the Android app pages products from dummyjson through the
KMP core into SQLite and back out, 19 contract fixtures pass on the JVM and through the app's
adapter, the coverage gates hold at 100% lines, and `make bench PLATFORM=android CORE=kmp` prints a
table. The Ralph loop built the product issues (#7–#17); the owner and an interactive session built
the gates and the loop itself alongside.

Sources: the `## Retro notes` comments on #53–#82, review comments and failed check runs on every
merged PR, and the loop's session logs (13 sessions).

## What was hard

Patterns, each seen at least twice:

- **The gh marker hook.** A PreToolUse hook denies `gh` publishes without the `🤖 … Claude Code`
  line. Seven of eleven sessions with notes hit it, almost always when ticking an issue checklist
  (#53, #60, #61, #62, #65, #70, #77). A denied Bash call runs none of its commands, so in #60 a
  `git commit` in the same call never ran and the PR opened one commit short; in #77 the body file
  didn't exist yet when the hook read it. No doc mentioned the hook. Fixed by #98.
- **Result shapes the issue didn't fix.** Sessions guessed contract result shapes and error codes
  in #54, #60, #61 and #62 (`invalid-json`, `not-a-product-page`, `{"productCount": n}`, the
  `nextFetch` URL). `contract/README.md` now documents every step's result, and M2's drafts spell
  out new shapes, rules and worked examples up front.
- **Android dependencies newer than compileSdk 36.** The Compose BOM (#55) and OkHttp 5.5.1 (#65)
  each needed SDK 37, which showed only at `checkDebugAarMetadata` after a slow first build.
  Fixed by #99.
- **A `VIRTUAL_ENV` from another worktree** made every `uv run` warn (#53, #65). Fixed by #100.
- **ktlint and detekt disagreed on line length** (140 vs 120) and on composable naming (#55, #69).
  Both were fixed in the PRs that hit them (#55's `detekt.yml`/`.editorconfig`, #70's
  `max_line_length`), so no further fix.
- **Structural commits missing from `.git-blame-ignore-revs`**: #63 (noticed in #69), then #87 and
  #91. A structural PR can't list its own squash SHA, so the step falls to the next PR and nothing
  checks it. Entries added in #126; a check is proposed in #129.

## What the gates caught

- **Review, hard findings:** wrong-typed prices accepted and non-page JSON throwing out of the core
  (#54); a missing commit, a re-ingest fixture blind to title and price changes, a test with no red
  run and a stale KDoc (#60, three review rounds); a structural PR with no `Closes` issue (#63,
  twice, resolved by filing #66); a credit line left in `CODING_STANDARDS.md` (#85); `ci` not yet
  required on `main` (#26).
- **Review, judgement notes:** tests with no red run (#70), an unused `junit-jupiter` catalog alias
  (#64, still on `main`), a malformed URL making OkHttp throw (#65), a broad emulator marker (#77).
- **pr-size:** #17's first attempt came to 424 lines; the session stopped with NEEDS_HUMAN and the
  issue was split into #75 and #17 (#77, #82). The `size-approved` label (#71) was never needed.
- **protected-paths:** fired on #89 and #93 as designed; both merged with `gate-approved`.
- **The review itself** was brought up during M1: it refused bot-authored PRs (#26, fixed by #27
  and #28), and was made to fail when denied tools (#30, #31).
- **CI** never failed on a merged loop PR; every red run was the review or a gate.

**Got past the gates:** core types leak past the app's adapter. `OkHttpFetcher` takes
`bench.core.FetchRequest` and `MainActivity` builds a `bench.core.Core` and converts the app's
`FetchRequest` back into the core's, against `CODING_STANDARDS.md`'s adapter rule. #69's retro
notes flagged it and #70 resolved it inside the coverage-excluded `MainActivity`; neither review
objected. #102 turns the rule into a detekt `ForbiddenImport` check and makes the app pass it, and
is M2's first issue.

## Coverage blind spots

- **Exclusions:** `bench.core.db.*` in core-kmp (SQLDelight output) and `bench.android.MainActivity`
  (entry point). No others.
- **`MainActivity` holds untested wiring**: the core construction and the `FetchRequest`
  conversion above. #102 moves both into the adapter, where they are tested.
- **Covered but not really tested:** the empty-database `page` fixture can't fail once the
  look-ahead row exists (#61); `IngestWorkloadTest` exists for the line gate rather than a
  behaviour (#82). Compose's generated skip branches count against the 95% branch gate (#70).
- **Outside the gate by design:** the contract runner lives in `:contract-runner` with its own
  tests, not under Kover's 100% (#53, #63).

## One-off friction

Kept for the next retro to spot a repeat:

- JUnit 5.13's platform launcher is versioned 1.13.x (#53).
- Gradle skipped the contract tests as up to date until `contract/cases` was a task input (#54).
- `@Serializable` classes fought the 100% gate; `JsonElement` tree decoding replaced them (#54).
- SQLDelight's default dialect has no `ON CONFLICT … DO UPDATE`; the upsert uses
  `INSERT OR REPLACE` (#60). ktlint linted SQLDelight's generated sources (#60).
- Integer-valued floats (`19` vs `19.0`) compare differently across cores; fixtures use fractional
  prices (#61). M2's drafts say so.
- An issue whose tests need a core type change it didn't mention (`headers` on `FetchRequest`, #65).
- macOS has no `timeout`; wrapping Gradle in it hid the real error (#70).
- A re-run issue's branch already existed on the remote with an older attempt (#82).
- `simpool` isn't on `PATH` in loop sessions (#82). M2's emulator issue (#120) gives its path; if
  M2 hits it again, the loop should put it on `PATH`.
- A test-first red run for a test that can't fail on first run (OkHttp doesn't throw on 500, #65;
  a negative guard, #70) needed a temporary break to show red.
